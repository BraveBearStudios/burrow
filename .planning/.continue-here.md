# BLOCKING CONSTRAINTS — Read Before Anything Else

> Each was discovered through an actual failure this session, not predicted.
> Acknowledge each explicitly before proceeding.

- [ ] CONSTRAINT: **rtk filters can return EMPTY for content that exists.** Measured twice —
      `rtk git diff --name-status <a>..<b>` returned nothing for two branches with real changes, and
      `rtk grep` returned 0 matches for patterns `node` confirmed present. Empty reads as "no
      changes" / "already merged", which is a specific, believable, wrong answer. Mitigation: use
      `rtk proxy git ...` for anything asserted as fact, and verify structural claims with `node`
      rather than a filtered grep.
- [ ] CONSTRAINT: **MSYS path rewriting can wedge a subagent indefinitely.** `gh api "/orgs/..."`
      became `C:/Program Files/Git/orgs/...`; the *next* Bash call then never returned and the agent
      sat for 19 hours, blocking the whole workflow run from exiting. Mitigation: `gh api` paths take
      no leading slash (or prefix `MSYS_NO_PATHCONV=1`); use `git show REV:PATH`, never
      `git rev-parse REV:PATH`; in subagent prompts, require short independently-runnable commands
      and "mark UNVERIFIED after two empty returns" rather than retrying.
- [ ] CONSTRAINT: **Three committed UAT commands produce a FALSE PASS.** They do not fail honestly —
      they report success regardless of the system's behaviour. See the anti-pattern table. Do not
      run the committed forms; use the corrected ones in the operator runbook artifact.

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| False-pass reap check | `$DEN "pct list \| grep 1020 \|\| echo GONE"` runs on den01 looking for a CT that lives on the second node. den01's list never held it, so the `\|\|` branch fires whether or not the reaper acted. | blocking | Run before/after checks on the second node, and assert positively on the `reaper.destroyed` log line. |
| Unrunnable orphan injection | `pct create ... --node <NODE2>` — `pct` has no `--node` option, and `$DEN` executes on den01, so the CT would land on the default node and invert the test. | blocking | `pct` is node-local. Hop: `ssh root@10.0.0.6 "ssh <NODE2> '...'"`. |
| Non-discriminating UAT-4d | `last4 before == after` holds even when decryption failed (last4 is plaintext), and `compute: ok` is satisfied by the `.env` fallback. | blocking | Assert the ABSENCE of the fallback log lines, with a GUI token whose last4 differs from the `.env` one. |
| `tee` suppresses the attestation banner | `gh attestation verify ... \| tee` hides the success line — gh gates it on stdout being a TTY. Combined with the exit-0 trap, a piped run yields no signal at all. | blocking | `script -qec '<cmd>' <file>`. |
| cosign four-line all-required assertion | The transparency-log line has two mutually exclusive forms. Requiring both produces a false FAIL on a good verification. **Confirmed live: this run printed the `verified offline` branch.** | advisory | Accept "offline OR online" for that one line. |
| Deploy Path A | main has moved past the commit that built `:1.4.1`, so a local build makes UAT-5 verify a different artifact than the one running. | blocking | Path B: pull the signed images, pin by digest, DELETE the `build:` blocks, never `--build`. |
| Squash merge | Ruleset `18189353` sets `allowed_merge_methods: ["rebase"]`. Squash succeeded on #24/#26 only because `--admin` bypasses the ruleset wholesale. | advisory | Use `--admin --rebase`. |
| Rebase-merge on a branch carrying applied commits | #25's rebase replayed its `wip:` commits onto main under new hashes; #24 and #26 still carried the originals, so GitHub refused with `This branch can't be rebased` rather than skipping the empties. Both stayed MERGEABLE — never a conflict. | advisory | Branch off `origin/main`, not local main, so a PR carries only its own commits. |
