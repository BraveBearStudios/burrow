## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Agent self-merging | `gh pr merge --admin` is classifier-denied; retrying or seeking an equivalent path defeats the guardrail | blocking | Surface the exact command for the operator to run with a `!` prefix; never substitute an API call that achieves the same mutation |
| Assuming the gh identity | The merge failed with `bcurry-arrow does not have the correct permissions`. Two accounts are logged in and the ACTIVE one lacks merge rights on this repo | blocking | Run `gh auth status` before any repo mutation; confirm the active account is `thezoid`, which has `admin:true` here |
| Waiting for a green PR | No PR in this set can go green alone — each reds on a CVE another PR owns | blocking | Read the job list, not the top-level conclusion. `Build + scan burrow-api` is the only failure on all of them |
| Guessed egress allowlist | Flipping egress to block without the run's Step-Security insights silently breaks cosign/OIDC/GHCR | blocking | Read insights per-workflow; flip ci.yml first, prove green, then release.yml |
| Faking operator work | Running discuss/plan/execute on Phases 20/22 produces fake progress; they need real hardware and creds | blocking | Verify status is `human_needed`; these close on operator evidence only |
| Verify by tag | `cosign verify` / `gh attestation verify` against a tag rather than the digest is unsound (T-14-01 exit-0 trap) | advisory | Verify by `@sha256:`; assert on printed OUTPUT, not exit code |
| Allowlisting a fixable CVE | RELX-05: a FIXABLE HIGH/CRITICAL is cleared by upgrade or removal, never by `.trivyignore` | advisory | Check the Status column; `fixed` means upgrade or remove the package |
